# 编排器协议:承包商模式

**计划批准后,编排器自主接管。**

## 循环

```
计划批准 → 编排器启动
  │
  第 1 步:实施 — 执行计划步骤
  │
  第 2 步:验证 — 运行脚本、检查日志与结构(见 verification-protocol)
  │         验证失败 → 修复 → 再验证
  │
  第 3 步:评审 — 按文件类型跑评审代理
  │
  第 4 步:修复 — 应用修复(严重 → 重要 → 轻微)
  │
  第 5 步:再验证 — 确认修复干净
  │
  第 6 步:评分 — 按 quality-gates 评分表
  │
  └── 分数 >= 阈值?
        YES → 向用户呈交摘要
        NO  → 回到第 3 步(最多 5 轮)
              超过上限 → 呈交摘要并列出遗留问题
```

## 限制

- **主循环:** 最多 5 轮评审-修复
- **批评-修复子循环:** 最多 5 轮
- **验证重试:** 最多 2 次
- 绝不无限循环

## 「直接做」模式

用户说「直接做」/「处理掉」时:
- 跳过最终批准暂停
- 分数 ≥ 80 自动提交
- 仍跑完整验证-评审-修复循环
- 仍呈交摘要
